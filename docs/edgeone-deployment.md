# EdgeOne Makers GitHub 自动部署

## 控制台配置

1. 登录腾讯云 [EdgeOne Makers 控制台](https://console.cloud.tencent.com/edgeone/makers)，选择免费版的「导入 Git 仓库」。
2. 选择 GitHub 并连接账号，仓库授权范围只选择 `XiaoyeCodes/Skill-Cabinet`。
3. 选择该仓库，项目名称填 `skill-cabinet`，生产分支为 `main`，根目录为仓库根目录。
4. 框架选择其他或静态网站。仓库中的 `edgeone.json` 指定安装命令 `node --version`、构建命令 `npm run build`、输出目录 `build/site`、Node.js `22.11.0`。此项目无需安装第三方依赖。
5. 选择免费可用的加速区域并开始部署；如有服务条款或额外授权，由账号所有者确认。长期访问可在控制台绑定自己的域名，域名费用与网站托管分开。
6. 在 Git 管理中确认部署仓库、生产分支 `main` 与自动部署开关，检查首次部署成功后，再通过一次 GitHub 推送核对新的部署提交。

Git 集成由 EdgeOne 控制台建立，提交本仓库的配置文件本身不会自动完成账号连接或创建云端项目。无需把 GitHub Token、腾讯云密钥写入代码、构建参数或网页文件。

## 发布包包含什么

运行 `npm run build` 会生成可直接托管的 `build/site/`，只包含网页静态文件、当前清单引用的技能 ZIP、分类、GitHub 项目目录和已提交的提示词。历史 ZIP、源码目录、测试产物和本地环境文件不会进入发布包。

构建前逐个校验技能 ZIP 的 SHA-256。EdgeOne 当前限制单个静态文件不超过 25 MB，所以超限的包拆成不超过 20 MB 的连续分片，分片表只写入发布产物的清单。浏览器按顺序合并分片，仍验证完整 ZIP 的原始 SHA-256 和技能指纹，导出时仍是完整技能包。GitHub 仓库保留原 ZIP 和原清单格式，本地运行与 GitHub 云同步不受分片影响。

构建目录不提交 Git。每次部署从指定分支重新生成，不会发布旧版未引用的技能包。HTML 与数据使用重新验证缓存策略，以便新发布生效。

## 数据保存与更新

- 本地运行仍用 `npm start`：分类和提示词按已有逻辑保存到本机仓库，提交并推送后触发网站更新。
- 公网页面展示构建时已提交的完整技能库；打开的页面每 5 秒检查清单，并保留用户在浏览器中的修改、删除和收藏。
- 线上页面的 Skill、项目和分类修改保存在当前浏览器，可使用现有「GitHub 云同步」写入自己授权的仓库。公开页面不会内置共用写入密钥。
- 提示词从发布包读取并与浏览器内容合并，同一条两边都有修改时继续提示选择版本。线上编辑只保存在当前浏览器，可导出备份，在本地项目中恢复后提交发布；当前 GitHub 云同步不包含提示词。
- 线上没有匿名写入项目文件的接口；浏览器中的导入、新建和编辑仍可使用，但不应将其理解为已经修改云端仓库。

## 免费额度与访问域名

按 2026-10-27 查询到的官方说明，免费版提供每月 500 次构建、5 GB 总存储、单文件 25 MB 限制。额度可能调整，以控制台和当期套餐说明为准。本项目使用静态托管，不需要开通付费服务器、数据库或 AI 模型服务。

系统预览地址可能有访问区域和有效期限制。需要长期公开分享时，请在控制台绑定自定义域名并按所选加速区域完成相应配置；购买域名是独立费用。本配置不购买域名或开启付费资源。
